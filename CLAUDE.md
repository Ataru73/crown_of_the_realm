# Crown of the Realm

A browser strategy and action game of medieval England, inspired by 1980s retro classics:
Saxon and Norman lords fight over England on a turn-based campaign map, with arcade
minigames for battles, tournaments, raids, rescues and sieges.

**IP policy:** All titles, character names, artwork, music, sound effects, and code must be
completely original. Never incorporate third-party trademarks, copyrighted imagery, audio,
or proprietary text. Art is generated with Gemini and music with Lyria in the Gemini app,
both through the browser. See `PLAN.md`.

`PLAN.md` holds the full design, asset pipeline and milestones. This file covers
how to work in the repo and where it stands.

## Commands

```bash
npm run dev        # Vite dev server (in WSL use: npx vite --port 5173 --strictPort --host 0.0.0.0)
npm test           # Vitest, all model tests
npm run typecheck
npm run build      # typecheck + production build into dist/
```

## Stack

TypeScript, **Phaser 3.90** (deliberately not Phaser 4), Vite, Vitest. The logical
resolution is 640×400 (`src/config.ts`), with `pixelArt` and `Scale.FIT`.

## Architecture

- `src/model/` holds all game rules. It is pure TypeScript and **never imports
  Phaser**, so every rule can be tested headless.
  - `types.ts` (GameState, Lord, Territory, Army), `map.ts`, `economy.ts`,
    `combat.ts` (field battle), `actions.ts` (one action per turn), `turn.ts`
    (`playTurn`, `endTurn`, `withRng`), `ai.ts`, `events.ts` (kidnap),
    `joust.ts`, `sword.ts`, `siege.ts`, `save.ts`, `setup.ts` (`newGame`).
  - Randomness only comes from the seeded RNG (`rng.ts`, mulberry32), and its
    state lives in `GameState.rngState`. Use `withRng(state, fn)`, never
    `Math.random`, in the model.
  - Rule violations throw `RuleError`, which the UI shows as a dialog.
- `src/scenes/`: one Phaser scene per screen. Scenes read `session.state`
  (`src/game/session.ts`) and call model functions.
- **Minigame flow:** MapScene starts the minigame scene. When it finishes, the
  minigame starts `Map` again with its result (`MapSceneData`: conquest,
  tournament, raid, rescue). Attacking a castle with catapults goes through
  SiegeScene first, which hands its `SiegeResult` (wall damage, fires) to
  BattleScene; `applySiege` turns it into the battle input. MapScene then plays that turn through
  `playTurn` with the outcome embedded in the action (`result` / `won`). With no
  outcome given, the model auto-resolves it, which is how AI lords act.
- `src/ui/` has the widgets (Button, Dialog, MapView, BuyDialog), the theme, and
  `assets.ts` (manifest loading, `addTinted`, `drawPainting`, `addParchment`).
- **Keyboard:** `Button` takes `keys` (Phaser key names) and an optional
  `keyLabel`. Dialogs register in `ui/modal.ts` (`pushModal`), so only the newest
  dialog's buttons answer keys; use `onKeys` for other shortcuts (it ignores
  auto-repeat and unhooks with its owner).
- **Settings:** `SettingsScene` is an overlay opened by Esc or the ⚙ button
  (`toggleSettings`); it pauses the scenes under it. The values (music and effects
  volume, mute) live in `src/game/settings.ts` and are applied by `ui/audio.ts`
  (`updateSettings`), stored under `crown-of-the-realm.settings`.
- `src/data/*.json` holds territories, heroes and lords. Territory `x`/`y` are pixels
  on the painted map (`public/assets/map.png`, 462×400).
- **Art:** `public/assets/` is generated by the pipeline in `tools/assets/` (see
  below); `src/data/assets.json` is its manifest and BootScene loads everything in it.
  Sprites with a `_tint` layer (`addTinted`) take the lord's colour: Gemini paints
  those areas pure green and `process.py` splits them out.
- **Saving:** the game autosaves to localStorage (`crown-of-the-realm.save`) at
  the start of each player turn. When `GameState` changes shape, bump
  `STATE_VERSION` (`state.ts`) and add a migration in `save.ts`. It is currently
  v2, with a v1 migration.

## Audio

`src/ui/audio.ts`: `playMusic(scene, track)` crossfades between looping tracks,
`sfx(scene, id)` plays an effect (its `volume` is scaled by the effects setting),
and the mute toggle (🔊 button, or M) is remembered with the settings. Sound effects are synthesised by `tools/assets/sfx.py`
into `public/assets/sfx/`; music is processed by `tools/assets/music.py` (90 s
loops with a crossfaded seam, stings trimmed) into `public/assets/music/`.

## Asset pipeline

1. Prompts, sizes and processing modes live in `tools/assets/prompts.yaml`
   (locked style: painted 16-bit Amiga pixel art).
2. Generate in Gemini (Edge, gemini.google.com). Gemini's downloads stall in Edge, and
   its CSP blocks fetches to localhost, so images are relayed instead: run
   `node tools/assets/receive.mjs`, open `http://localhost:5199/` from the Gemini tab
   with `window.open` (needs a real click), then draw the `<img>` to a canvas and
   `postMessage({ id, blob })` to that window. It saves `raw-assets/<id>.png` (git-ignored).
3. `tools/assets/.venv/bin/python tools/assets/process.py [id ...]` crops, keys out
   the magenta, splits tint layers and reduces the palette into `public/assets/`.
   The venv has Pillow, PyYAML and numpy (create it with
   `python3 -m venv --without-pip tools/assets/.venv` and
   `pip3 --python tools/assets/.venv/bin/python install pillow pyyaml numpy`).
4. Anchor points in the art (the joust knight's shield, the swordsmen's feet and
   hands, the lance butt) are constants in the scenes; re-measure them after
   regenerating a sprite.

## Conventions

- Put new rules in `src/model` with Vitest tests. Use the helpers in
  `tests/helpers.ts` (`game(seed)`, `memoryStorage`).
- `tests/balance.test.ts` simulates 100 AI campaigns and checks that every game
  finishes, plus broad statistics. Rerun it after any rule change.
- Do the real-time minigame logic in the model as a `tick(dt)` state machine
  that emits events, as in `sword.ts`. The scene drains the events for effects
  and poses the sprites from the phases.
- Verify UI changes in the browser (Edge through the claude-in-chrome extension, at
  `http://localhost:5173`). In dev builds the Phaser game is available as
  `window.game`, and model modules can be loaded with `await import('/src/model/...')`.
  The tab is throttled to about 6 fps when it is in the background, so wait
  generously.
- Commits: one per milestone, with messages like `M5: ...`, on `main`. There is
  no remote yet.

## Deploy

`.github/workflows/deploy.yml` runs the tests, builds and publishes `dist/` to
GitHub Pages on push to `main`. The repo has no remote yet; once it's on GitHub,
set Pages > Source to "GitHub Actions".

### Known issues / deferred
- Balance: the three Saxon home counties have income 7 (Normans were winning 83%
  of simulated games). The AI-played hero now wins ~40%, Normans ~40%, Saxon
  rivals ~20%, but games average ~90 months. The sim is chaotic: small rule changes
  swing the results a lot, so rerun the balance test after any change.
- Music: all 9 tracks exist. `playMusic` stays silent for any track missing from
  `src/data/music.json`. When regenerating: Lyria makes one ~3-minute take per chat
  and often fails in a long chat, so start a new chat per track; the take is a
  `<video>` (mp4) whose src can be fetched and relayed as audio/mp4.
- Units have a single pose each (no animation frames); adding them needs a new
  Gemini art pass.
- Quitting to the title from a minigame and pressing Continue replays the month
  from its autosave, so a lost joust or fight can be retried.
- The siege was tested in the browser by driving the scene from JS; the Attack
  button's routing to it and a full hold-and-release play by hand are untested.
- Not yet tested by hand in the browser (the model tests cover these): bombard,
  a won joust, jousting for land, a full game ending in defeat (the screen and its
  music were checked by starting the scene directly).
